## 1. Executive Summary

This document describes the complete reverse-engineering and reconfiguration procedure used to convert a locked, ISP-provisioned **Comtrend / Jio JRDU4311 Reverse Multi-Dwelling Unit (RMDU)** into an **unmanaged, wirespeed 8-port Gigabit Ethernet switch**.

All vendor port isolation (`ISO 70082` → `ISO 700ff`), carrier VLAN tags (VLAN 960/1015/1022), TR-069 remote management, and background MQTT telemetry daemons have been permanently disabled in persistent flash (`/hw_setting/hw.bin`). The device now powers up as a standard flat switch forwarding between all ports at gigabit line rate without any phone-home activity.

---

## 2. Hardware Specifications

- **Device Name:** Commodity Reverse-Multi Dwelling Unit (JRDU4311 / JRDU4301)
- **Vendor:** Comtrend (OEM for Reliance Jio Infocomm)
- **MAC Address:** Printed on bottom label (Format: `A0:18:42:xx:xx:xx`)
- **Serial (RSN):** Printed on bottom label
- **Main SoC:** Realtek RTL8197F-VG (MIPS 24Kc @ 400 MHz)
- **Switch Chip:** Realtek RTL8370B Gigabit Ethernet Switch ASIC
- **Flash Storage:** Macronix MX35LF1GE4AB 128 MiB SPI NAND Flash
- **RAM:** 64 MiB DDR2
- **Power Architecture (Reverse PoE):**
  - **OEM Power Supply Rating:** 54V DC, 0.56A, 30.00W Max (Standard Reverse PoE injector supplied with unit).
  - **Ports 1–7 (Yellow):** 10/100/1000BASE-T Ethernet with PoE **Input** (48–56V DC). Built with diode-isolated PD (Powered Device) circuits to receive power from customer apartments or PoE injectors.
  - **Port 8 (Blue):** 10/100/1000BASE-T Ethernet with PoE **Output** (PSE – Power Sourcing Equipment, 48–56V DC up to 25W, 802.3af/at). Powered by an internal Texas Instruments MSP430 MCU and eFuse power controller.
- **Serial Console:**
  - Connection: 3.3V UART header
  - Parameters: **38400 baud**, 8 data bits, no parity, 1 stop bit (38400 8N1). *Note: NOT standard 115200 baud.*

## 3. Credentials & Account Architecture

### 3.1 Discovered Accounts

| Interface | Username | Plaintext Password | Port | Flash MIB Key / Base64 Hash |
| :--- | :--- | :--- | :--- | :--- |
| **UART Serial Shell** | `root` | `YG*vd2!C2DL=LYXn3ni@` | Serial (38400) | `SUPER_ADMIN_USER_PASSWORD="WUcqdmQyIUMyREw9TFlYbjNuaUA="` |
| **SSH (Dropbear)** | `root` | `YG*vd2!C2DL=LYXn3ni@` | TCP 22 | `SSH_ENABLE=1` (Dropbear v2020.81) |
| **Telnet** | `root` | `YG*vd2!C2DL=LYXn3ni@` | TCP 23 | `TELNET_ENABLE=1` (BusyBox telnetd) |
| **Web UI (HTTP/HTTPS)** | `admin` | `JRDU4311<lowercase_mac_no_colons>` | TCP 80 / 443 | Derived dynamically from MAC address |
| **System Service Account** | `jio` | *(Service account for Boa)* | N/A | UID 1000, GID 0 (Defined in `/etc/passwd_orig`) |

### 3.2 How Credentials Work at Boot
- `/etc/passwd` and `/etc/shadow` are dynamic symlinks pointing to `/var/passwd` and `/var/shadow` in RAM.
- At boot, `/etc/init.d/rcS_GW` calls `/bin/sysconf`.
- `/bin/sysconf` reads `SUPER_ADMIN_USER_PASSWORD` from the flash configuration blob (`/hw_setting/hw.bin`), Base64-decodes it into `YG*vd2!C2DL=LYXn3ni@`, and executes:
  ```sh
  echo "root:YG*vd2!C2DL=LYXn3ni@" | chpasswd -m
  ```
  *(This root password is hardcoded across all devices of this model).*
- The password for `admin` on the web interface is generated by the vendor from the model prefix (`JRDU4311`) concatenated with the lowercase MAC address without colons (e.g. `JRDU4311a01842xxxxxx`).
- **Note on "Superadmin":** There is no separate `superadmin` user account in `/etc/passwd` or on the Web UI. The MIB name `SUPER_ADMIN_USER_PASSWORD` is simply Realtek's internal variable name for the console `root` account.

### 3.3 Network Shell Access (SSH & Telnet)
- The firmware contains **Dropbear SSH** (`/bin/dropbear`) and **BusyBox Telnet** (`/bin/telnetd`).
- By default, the ISP firmware disabled them at boot by creating `/var/disable_ssh` and `/var/disable_telnet`.
- They can be enabled permanently in flash by setting:
  ```sh
  flash set SSH_ENABLE 1
  flash set TELNET_ENABLE 1
  ```
- Both daemons launch automatically on boot once set:
  ```sh
  # SSH connection
  ssh root@192.168.33.1
  # (Password: YG*vd2!C2DL=LYXn3ni@)

  # Telnet connection
  telnet 192.168.33.1
  # (Login: root / Password: YG*vd2!C2DL=LYXn3ni@)
  ```

## 4. Initial Blockers Identified

Before conversion, the stock firmware blocked standard switch operation via three independent mechanisms:

1. **Hardware Port Isolation (`ISO 70082`):**
   The RTL8370B switch ASIC had port isolation active (`ISOLATION_CFG=1`, `PORT_ISOLATION_MASK_GROUP1=127`). Downstream ports (Ports 1–7) were masked to only allow forwarding to Port 8 (uplink) and the CPU. Ports 1–7 could **not** communicate with each other.
2. **VLAN Segregation:**
   - `VLAN_ENABLED=1`, `VLAN_OPMODE=1`, `PORT_VLAN_TRUNK=0101010101010101`.
   - The device enforced tagged VLAN 960 (management plane), VLAN 1015 (data), and VLAN 1022. Untagged packets on local ports were dropped or isolated.
   - The Linux bridge (`br0`) only bridged the tagged virtual interface `eth0.960`.
3. **Active Telemetry & Phone-Home Services:**
   - **TR-069 / CWMP:** `cwmpClient` continuously polled `https://acs.oss.jio.com:8443/ftacs-digest/ACS`.
   - **MQTT Telemetry:** `data_collect` collected system metrics every 300 seconds and invoked `paho_cs_pub` to publish encrypted packets to `ssl://rmdu.dinj.jfdca.net:1887`.

## 5. Step-by-Step Manual Conversion Procedure (UART)

If connecting via the 3.3V UART serial console (`/dev/ttyUSB0` @ 38400 baud):

### Step 1: Back Up Existing Configuration
Before modifying any settings, create persistent backup copies of the active configuration binary:
```sh
cp /hw_setting/hw.bin /hw_setting/hw.bin.orig
cp /hw_setting/hw.bin /var/tmp/data/hw.bin.orig
sync
```

### Step 2: Disable Port Isolation
Disable isolation across the entire port group so all ports forward to each other:
```sh
# Disable port isolation in runtime and flash MIB
port -i 0

# Clear isolation mask group 1
flash set PORT_ISOLATION_MASK_GROUP1 0
```
**Verification:** Run `cat /proc/rtl865x/port_status`. The port status flag changes from `ISO 70082` to `ISO 700ff` (mask `0x700ff` represents all 8 physical ports plus CPU ports).

### Step 3: Disable VLANs and Flatten the Bridge
Strip the carrier VLAN tags and place raw `eth0` directly into bridge `br0`:
```sh
# Disable VLAN subsystem in flash
vlan -e 0
flash set VLAN_ENABLED 0
```

### Step 4: Disable TR-069 (CWMP) and Jio Telemetry
Permanently disable the remote management client and MQTT phone-home reporting:
```sh
# Disable TR-069 via control utility (clears bit 5 in CWMP_FLAG from 160 to 128)
tr069 set tr069_enable 0

# Disable CWMP inform triggers
flash set CWMP_ENABLED 0
flash set CWMP_INFORM_ENABLE 0

# Disable Jio MQTT metrics collector
flash set MQTT_ENABLE 0

# Stop any running instances immediately
killall cwmpClient 2>/dev/null
killall data_collect 2>/dev/null
killall paho_cs_pub 2>/dev/null
killall paho_c_pub 2>/dev/null
```

### Step 5: Save Working Configuration Copy & Reboot
```sh
# Save persistent backup of the modified configuration
cp /hw_setting/hw.bin /hw_setting/hw.bin.flat_switch_v2
cp /hw_setting/hw.bin /var/tmp/data/hw.bin.flat_switch_v2
sync

# Reboot to verify persistence
reboot
```

## 7. Port 8 (Blue PoE Out) Safety & Usage Rules

- **Power Specifications:** Port 8 provides **48V–56V DC (up to 25W)** compliant with IEEE 802.3af/at.
- **Compatible Devices:** Standard 48V PoE Access Points (UniFi, Omada), 48V PoE IP cameras, or 48V VoIP phones.
- **Power Budget with Stock Adapter (30W):** 
  - The RMDU requires ~8W–12W for its own internal operation (SoC, switch ASIC, LEDs, and PHYs).
  - With the stock **54V 0.56A (30.00W)** injector, the remaining power budget on Port 8 is approximately **15W–18W** — sufficient to power standard IEEE 802.3af (Class 3) PoE devices such as basic Wi-Fi Access Points, VoIP desk phones, or IP cameras.
  - If powering power-hungry IEEE 802.3at (Class 4, 25W+) devices on Port 8, an upgraded upstream injector (e.g. 45W–60W / 802.3bt) is recommended.
- **DANGER:** 
  - **Do NOT connect 24V passive PoE devices** (e.g. older airMAX gear) — 48V will destroy them.
  - **Do NOT connect standard client PCs/laptops** to Port 8 — keep non-PoE devices on Ports 1–7.

## 8. Web Management Access

The RMDU web interface remains functional for switch monitoring, Virtual Cable Testing (VCT), and port mirroring.

- **URL:** `http://192.168.33.1/` (or `https://192.168.33.1/`)
- **Username:** `admin`
- **Password:** `JRDU4311<lowercase_mac_no_colons>`

### Dual-IP Setup on Linux Host:
To browse the Web UI without losing normal home internet access, configure a secondary static IP alias on your client PC:

1. **Secondary Static IP Alias for Web UI Access:**
   ```sh
   nmcli con mod "Wired connection 1" +ipv4.addresses 192.168.33.2/24
   nmcli con up "Wired connection 1"
   ```
   *Reason:* The RMDU has static fallback management IP `192.168.33.1/24`. Adding `192.168.33.2/24` as an alias allows direct communication with the switch UI at `http://192.168.33.1/` while DHCP retains `192.168.1.x` for Internet.

2. **How to Revert Client Settings to Default:**
   ```sh
   nmcli con mod "Wired connection 1" -ipv4.addresses 192.168.33.2/24
   nmcli con up "Wired connection 1"
   ```

## 9. Automated Zero-Touch Conversion (No UART / No Case Teardown)

Opening the RMDU chassis and soldering headers to 38400 baud UART pins is **not required** when setting up new units. The firmware contains built-in remote service triggers in its web server (`/bin/boa`) that allow enabling SSH over Ethernet in a single step.

### 9.1 The Web Trigger Mechanism
Analysis of the disassembled Boa binary (`/bin/boa`, function `process_header_end`) revealed two vendor control URIs:
- `http://192.168.33.1/SSH_ENABLE`
- `http://192.168.33.1/TELNET_ENABLE`

When Boa receives an HTTP request for `/SSH_ENABLE`:
1. It immediately invokes `flash set SSH_ENABLE 1` to persist the configuration change in NAND flash.
2. It removes `/var/disable_ssh`.
3. It signals the supervisor process via `killall -SIGUSR1 helper`.
4. The `/bin/helper` daemon catches `SIGUSR1` and immediately starts **Dropbear SSH** (`dropbear -B`) on TCP port 22.
5. In Boa's request parsing loop, this check is evaluated before HTTP Basic Authentication or session checks, returning `HTTP/1.1 204 No Content` to the caller.

### 9.2 Factory Device Network Topology Rule
On a factory-sealed, un-configured RMDU:
- The internal bridge `br0` (`192.168.33.1`) is isolated behind **VLAN 960** (management VLAN).
- In the factory switch ASIC configuration (`vlanTable[1]`), VLAN 960 is **only a member on Port 1, Port 8, and CPU**:
  ```text
  vlanTable[1] = '960|0|port1, port8, management|'
  ```
  Ports 2–7 are tenant data ports and strictly **drop** VLAN 960 in hardware.
- Therefore:
  - The PC Ethernet cable **MUST be connected to Port 1 (Yellow)** during initial provisioning.
  - The PoE power injector can be plugged into **any other port** (e.g., Port 2 or Port 3).
  - The host PC must tag outgoing frames with **VLAN ID 960** to communicate with `192.168.33.1`.

### 9.3 Turnkey Python Provisioning Script
A complete turnkey script is included: [`provision_new_rmdu.py`](provision_new_rmdu.py).

#### How to run it:
1. Power up the fresh RMDU (via PoE injector on any Yellow port 2–7).
2. Connect your Linux laptop's Ethernet cable specifically to **Port 1 (Yellow)**.
3. Run the provisioning script as root:
   ```sh
   sudo ./provision_new_rmdu.py
   ```
   *(Or optionally pass the interface directly: `sudo ./provision_new_rmdu.py eth0`)*

#### Interactive User Experience:
The script automatically inventories host network cards, detects which Ethernet port has an active link, highlights it with `[RECOMMENDED]`, and lets you select it by simply pressing **Enter**:
```text
Available Network Adapters:
============================================================================
 #   Interface         Type       Link Status              Speed     
----------------------------------------------------------------------------
 [1] eth0              Ethernet   LINK UP (Connected)      1000 Mbps  [RECOMMENDED]
     └─ MAC: 00:11:22:33:44:55
 [2] wlan0             Wi-Fi      LINK UP (Connected)                
     └─ MAC: aa:bb:cc:dd:ee:ff
============================================================================
Select adapter [1-2] (default: 1): 
```

#### What the script does automatically:
1. **VLAN 960 Setup**: Creates 802.1Q subinterface (`vlan960`) with IP `192.168.33.2/24` to communicate with the switch's factory management plane. Includes signal trapping so Ctrl+C cleans up the interface automatically.
2. **Boot Polling**: Displays a live progress countdown while waiting for the RMDU to finish booting.
3. **SSH Remote Activation**: Sends HTTP GET to `/SSH_ENABLE`, activating Dropbear SSH in memory and saving `SSH_ENABLE=1` to persistent flash.
4. **SSH Execution Pipeline**: Authenticates as `root:YG*vd2!C2DL=LYXn3ni@` and executes the conversion steps:
   - Removes port isolation (`port -i 0` & `flash set PORT_ISOLATION_MASK_GROUP1 0`).
   - Disables carrier VLANs in flash MIB (`vlan -e 0; flash set VLAN_ENABLED 0`).
   - Kills TR-069 and Jio MQTT telemetry (`tr069 set tr069_enable 0`, `flash set CWMP_ENABLED 0`, `flash set MQTT_ENABLE 0`).
   - Permanently enables SSH and Telnet in flash MIB (`SSH_ENABLE=1`, `TELNET_ENABLE=1`).
5. **Reboot & Cleanup**: Sends `reboot` command, tears down the temporary host VLAN interface, waits for the switch to reboot into flat mode, and automatically restores your client PC's adapter to normal DHCP.
